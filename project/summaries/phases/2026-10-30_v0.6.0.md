# Session summary: v0.6.0 (2026-10-30)

**Goal.** Fix the regression SwiftMoE found (connections past the cap closed with no answer), decide the other differences its
replay found, and do the public API audit.

**Done.**
- Busy refusal: `BusyRefusalHandler`, `ConnectionRegistry` admission (admitted / refuse / drop, 32 refusal slots, 2 s deadline),
  `Limits.busyRetryAfter`, `TransportRefusal.busy`. TLS stays close-before-handshake (measured ~7.5x CPU for the handshake).
- Wire differences: 408 for a silent first connection, 505 for another major version (HeadGuard reads the request line),
  RFC 9110 phrases for 413/416/422. A stalled body already got 408.
- Audit: `connections` renamed `connectionReuse` with a one-release shim; Hashable on value types; `RefusalRecord.init` public;
  `Request.init` typed. Full table in `DesignProposal_0.6.0.md`.
- 17 hand mutants, 16 killed, 1 equivalent. Consumers: three compile unchanged, SwiftMoE needs two `case` lines.

**Decisions to know.** Refusal count and deadline are constants, not parameters. New `TransportRefusal` cases break exhaustive switches.

**Next.** Remove the `connections` shim by 1.0.0. Soak, Linux CI, fuzzing, outside review (see master plan).
